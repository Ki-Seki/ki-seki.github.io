## 1.1 建设目标与应用场景

为支持 Craft 的训练数据分析与定向筛选，我们构建了面向大规模训练数据的交互式图文检索与类簇浏览工具，帮助研究与数据团队从样本与类簇两个层面查找和检查数据，并查看其内容、标注与来源。主要应用场景包括：

- **预训练数据筛选、清理与配比。** 通过类簇搜索与代表样本浏览检查数据分布，按既定安全与质量策略审核和剔除 NSFW 等不合格样本或类簇，并调整不同类簇或数据源的采样权重与配额，提高或降低其在训练集中的占比。

- **后训练数据回捞与筛选。** 围绕模型薄弱项、目标样例和特定能力需求，从数据池中检索、回捞相关候选样本，经人工筛选、质量检查和必要标注后组织为数据集，为 SFT 与 RL 中的特定能力增强提供数据支持。

- **评测数据泄漏风险排查。** 将评测图像或构建评测提示词时使用的参考图片作为查询，单独或批量检索相同及近重复的训练样本，辅助排查训练与评测数据的重合。近似检索未命中不等同于训练数据中不存在该样本。

## 1.2 大规模离线索引构建

系统由离线索引构建和在线检索服务两部分组成。离线阶段包括数据清单整理与样本映射、图像表征提取、聚类与向量量化、分片索引构建及完整性校验。我们采用 SigLIP2 提取图像表征，并基于 FAISS，将倒排文件索引（Inverted File，IVF）与乘积量化（Product Quantization，PQ）结合，构建压缩检索索引。

### 1.2.1 数据准备与图像表征

大规模、多阶段训练中的数据筛选、重采样与标注迭代可能形成数十种派生数据集或版本，增加数据管理和样本追溯的难度。为此，我们统一采用 Main Parquet 与 Sidecar Parquet 的组织方式：Main 保存图像数据或引用，Sidecar 保存与其逐行对齐的描述、布局等标注与属性，使标注更新不必重写图像数据。样本通过 `(dataset_revision_id, source_file_id, source_row)` 三元组统一定位，分别对应数据集版本、源分片编号和分片内行号，便于统一访问与来源追溯。

我们首先根据待检索的数据范围整理输入清单，以 Parquet 分片为处理单位，记录源文件位置与行数。图像既可从分片内嵌的图片字节读取，也可从分片记录的 S3 路径获取，随后按固定配置完成解码、尺寸调整和像素归一化。

图像编码采用 SigLIP2 SO400M（patch14，384 × 384 输入），为有效图像生成 1,152 维向量，经 L2 归一化后以 FP16 存储。在线查询使用同一模型的图像或文本编码器，将参考图片和文本映射到共享表征空间，从而在同一图像索引上支持以图搜图和以文搜图。

### 1.2.2 分布式表征提取

对于十亿级图像数据，表征提取不仅涉及 GPU 推理，还包含对象存储读取、图像解码和结果写出。我们以 Parquet 分片为任务单元，按分片大小估计初始负载，将任务分配到多个计算节点，并由节点内的多个 GPU 工作进程并行处理，各分片独立写出结果。

不同图片格式、尺寸和存储读取延迟会造成任务耗时不均。我们从数据供给、推理组批和任务调度三个方面提高处理效率：

- **流水线重叠与有界预取。** 在 GPU 计算当前批次时提前准备后续数据，使读取、解码与推理尽量重叠，减少 GPU 等待数据的时间；同时限制每个进程在途的分片数量，避免过量占用资源。

- **跨分片组批。** 在同一工作进程内，将不同 Parquet 分片中就绪且解码路径相同的图片合并为推理批次，减少分片边界或数据筛选造成的小批次推理，提高批次填充率。推理结果仍按原始分片和行号回写，保持样本对应关系。

- **节点内动态任务调度。** 工作进程完成任务后继续领取尚未处理的分片，配合有限的提前领取窗口，避免少数进程积压慢任务而其他进程空闲，缓解负载不均与任务收尾时的长尾等待，缩短整批任务的完成时间。

为降低长时间任务中断后的重算成本，我们按分片内的数据块保存检查点。恢复时保持输入清单、编码配置和数据块划分不变，跳过已完成分片，并复用未完成分片内的有效检查点；对缺失输出单独生成补跑清单，避免全量重算。

构建完成后，核对源分片与输出的覆盖范围和行数，汇总下载、解码等失败状态，并抽查样本标识的对应关系以及向量的维度、数据类型和 L2 范数。失败样本保留原始位置与状态，避免因直接丢弃记录造成行号错位；缺失或异常输出需处理并复核后再交付，而不以任务进程结束作为完成依据。

### 1.2.3 聚类与压缩索引

按每张图像对应一个 1,152 维 FP16 向量计算，十亿张图像仅向量数值就占 2.304 TB（十进制，不含图像、标注及文件格式开销），逐一比较也难以满足交实时检索需求。我们采用 IVF-PQ，将缩小搜索范围与向量压缩结合。

聚类中心与 PQ 码本均在抽样 N 条向量数据上训练。以 1.4B 预训练库的参考构建配置为例，N=0.1B：按各输入 embedding 分片的行数比例分配配额，再在每个分片内按行区间分层抽样，按行区间读取。这种分层块抽样可利用对象存储的范围读取，避免为取少量样本下载整个向量文件；它并非逐行独立的全局均匀随机抽样。该样本集划分为 9900 万条 IVF 训练样本与 100 万条留出样本，后者只用于该阶段的聚类评估。

IVF 的簇数预设为 `K=10,000`，训练根据上述 9900 万条向量学习中心位置。随后将全量向量分配到最接近的中心，并将同一簇的样本组织为倒排列表。查询时先找到与查询向量接近的若干中心，再扫描对应列表，避免遍历整个数据集。

在压缩方面，我们对向量与所属聚类中心之差，即残差，进行乘积量化（PQ）。上述配置从同一份 1 亿条样本资产中，按样本分片均衡分配读取配额、取各分片的前缀，共选取 210 万条向量，其中 200 万条用于 PQ 训练，10 万条留出用于量化重构误差评估。

PQ 的分段数与每段编码位数也由配置决定：这里采用 64 段、每段 8 位的 PQ64 配置，每段为 18 维，8 位编号对应每个子码本中的 256 个代表向量。先计算 PQ 训练样本相对于已确定的 IVF 中心的残差，再汇集各 IVF 簇中相同段位置的子向量，分别执行 256 类的 K-means，得到 64 套在整个索引中共享的码本。

编码时，每个残差子向量选择对应码本中最近的代表向量，仅保存其 0–255 的编号。由此，原本占 2,304 字节的 1,152 维 FP16 向量被表示为 64 字节的量化编码。

聚类中心和 PQ 码本确定后，全量簇分配与编码可分布式执行。随后将样本标识和量化编码按簇归并，组装为多个 FAISS 索引分片；同一索引的各分片共享中心与码本。索引的聚类数、PQ 编码长度与查询时探测的簇数（`nprobe`）共同影响资源开销与检索效果：增加探测簇数通常有助于提高召回，但需要扫描更多候选；PQ 则以量化误差换取更低的存储与扫描成本，因此基于该索引的召回属于近似检索。

## 1.3 在线检索与样本检查

在线检索接受参考图像、文本或二者的组合。系统使用与离线建库配套的 SigLIP2 编码器生成归一化查询向量；多图或图文输入可先汇聚为一个查询向量，也可分别召回后按相似度或排名融合结果。每路查询并行搜索各索引分片，服务端按样本标识合并去重，并按 PQ 近似距离排序保留候选。为辅助结果核验，系统对指定数量的前排候选回源读取图像，按当前编码配置重新生成完整向量，计算不经 PQ 近似的余弦相似度，并支持在这些候选内重排。

结果浏览将检索排名与样本内容、标注和来源关联起来。用户可从缩略图进入详情，查看描述文本、原始 JSON 及与标注对齐的展示图，通过图上边界框与结构化元素的联动检查布局和描述是否一致；数据集版本、源文件路径和行号则用于定位底层训练记录。

针对一组模型坏例或评测样本，批量独立查询可逐条检索并对照结果，减少反复提交单次查询的操作。研究人员可按数据来源、尺寸等属性缩小候选范围，将人工选定的样本整理为跨查询保留的素材集，并导出包含源路径和行号的 JSONL 清单，衔接后续数据回捞、复核和重标注。查询参数与结果快照还可保存为分享链接，便于团队围绕同一批候选协作检查。
